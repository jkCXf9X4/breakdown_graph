# Git owns the solution boundary

## Purpose

The integrator planning parallel work uses this node as the isolation promise;
without it, a view or a work folder is mistaken for a branch.

---

A solution is isolated by git, not by the store: one branch and worktree per
solution, and git decides when it merges or is discarded. `bd` sees only the
checkout it runs in; refs carry no branch name, no command reads git state,
and neither a view nor a version crosses a branch
(`docs/BRANCHES-AND-VERSIONS.md:3-20`, `docs/BRANCHES-AND-VERSIONS.md:34-65`). A
store that modelled branches would need a live pointer per node and would let
branches diverge silently. It realizes
(Large trees need a bounded agent context)[[12-1, realizes]] by keeping an alternative
out of the shared tree. It is falsified if a ref resolves through a branch name,
or if a view needs a merge to be read
(`AGENTS.md:93-95`).
