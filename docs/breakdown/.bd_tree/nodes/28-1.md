# Node files are the only source of truth

A store is a flat `nodes/` directory of markdown files named by ref, and every other surface is regenerated from it.

- **Layout:** `.bd_tree/nodes/<ref>.md` in a project layout, `<dir>/nodes/<ref>.md` in a classic store.
- **Flatness:** no subdirectories; identity comes from the filename, so a title change moves no file.
- **File content:** YAML front matter carries `links` and user metadata, and the body stays byte-identical under structural edits.
- **Derived surfaces:** `INDEX.md`, `REFS.md`, `AGENTS.md`, view output, and exports are regenerated and never hand-edited.
- **Load path:** `scan()` reads `root/nodes` once and returns records plus global issues such as `invalid-filename` and `bare-ref` (`src/bd_tree/loader.py:467`).
- **Commits:** node files are tracked; `bd_work/` and exported output are ignored.
- **Traces to:** one store yields many read-only projections (22-1).
