# The work area is a flat symlink layout

## Purpose

The author or agent editing through the work area uses this claim to tell a store
path from a copy; without it, an edit is made in a detached file and never
reaches the store.

---

The work area is a layout, not a copy. `<project>/bd_work/` is flat: one relative
symlink per materialized ref, named after the store basename, while `INDEX.md`,
`AGENTS.md`, and `REFS.md` are generated regular files reserved in every
directory (`docs/DESIGN.md:301-305`, `AGENTS.md:96-99`). Editing a link edits the
store, with no copy and no sync layer (`docs/DESIGN.md:301-305`). `bd work REF`
replaces the area with one view, and `REF+N` materializes rings `0..N` while the
view stays the whole component (`docs/DESIGN.md:306-319`). The active view is the
ref in the `REFS.md` header, so no extra state file exists
(`docs/DESIGN.md:320-322`). One flat area holding the whole slice without a
second store is what realizes
(One project has one writable work area)[[16-1, realizes]]. It is falsified
by a copied node file, a sync layer, or an area holding two views.
