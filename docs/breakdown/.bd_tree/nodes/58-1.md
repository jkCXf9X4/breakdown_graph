# Windows symlink support

The work area is built from POSIX symlinks, and Windows needs developer mode or elevated rights to create them.

- **Current behavior:** Windows users must enable developer mode, and there is no Windows-specific symlink path in the tool.
- **Cost:** The primary work-area interface is unavailable or privilege-dependent on a supported desktop platform.
- **Possible direction:** Add a junctions or copy-backed layout behind the same generated files, while keeping the store the only source of truth.
- **Constraint:** A copy-backed area reintroduces sync, so the fallback must stay visibly derived and disposable.
