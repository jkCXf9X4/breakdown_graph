# Exit codes separate navigation, structure, and success

`cli.main` returns 0 from a handler, 1 for `NavigationError` or a failed check, and 2 for `BreakdownError`.

- **Success:** handlers return 0 after printing, and `check` returns 0 when `CheckResult.ok` is true.
- **Navigation failure:** `navigate.NavigationError` is caught first, printed to stderr, and mapped to 1.
- **Structural refusal:** `BreakdownError` and its subclasses are caught next and mapped to 2.
- **Check failure:** `_cmd_check` returns `0 if result.ok else 1`; a clean store exits 0 and an error exits 1.
- **Status failure:** `bd work --status` and `--writeback` return 0 only when every entry is `ok`, else 1.
- **Shell use:** scripts distinguish a missing ref from a refused edit without parsing messages.
- **Verifies:** CLI and API share one command surface (31-1).
