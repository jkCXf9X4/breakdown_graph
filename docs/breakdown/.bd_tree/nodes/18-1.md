# Layered breakdowns lose credibility across handovers

A layered breakdown degrades at handover because a top-layer change leaves the nodes beneath it asserting the old solution, and nothing marks the mismatch.

- **Propagation gap:** a change in intent, claims, or argument leaves evidence and manuscript nodes stating the previous solution.
- **Invisible downstream:** the stale node is neither repaired nor detected at the next layer, so the loss surfaces only on inspection.
- **Two truths:** an agent reading the repository sees both layers and cannot tell which is current.
- **Branch limit:** one git branch over the whole tree cannot show two variants side by side; deleting the old branch is the only well-defined removal and loses its reasoning.
- **Diagnosis applied:** dependencies become explicit, a view becomes a declared closure, and stale material is reported rather than silently present.
