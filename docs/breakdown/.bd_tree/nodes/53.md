# Cross-branch version synchronization

Versions are node-local files, so a version created on one branch is absent on another until the branches merge.

- **Current behavior:** A version exists only in the checkout that tracks its file; git merges whole files and carries no per-version identity.
- **Cost:** Parallel branches can create unrelated versions of the same node, and reconciling them is left to whoever notices the drift.
- **Possible direction:** Add a merge-time check or sync verb that reports version sets per id across branches, without making a version a cross-branch ref.
- **Constraint:** A view never crosses a branch, so synchronization must end at a git merge rather than introduce a branch selector.
