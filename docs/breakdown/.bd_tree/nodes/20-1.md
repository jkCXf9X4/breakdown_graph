# Git owns the solution boundary

A git branch and worktree isolate a whole solution; the flat store is the merge unit, and a view is a lens inside one checkout.

- **Solution:** `bd solution new NAME` wraps `git worktree add ../NAME -b NAME`, one worktree per solution.
- **Merge unit:** one file per ref keeps a conflict local to `.bd_tree/nodes/<ref>.md` (or `nodes/<ref>.md`).
- **Lens:** `bd work REF` changes the layout inside one checkout and is never a branch mechanism.
- **No crossing:** a view and a version never cross a branch, and refs carry no branch name.
- **Version scope:** `5-1` is one of the peer versions of node `5` in the checked-out branch, with no isolation and no separate history.
- **Wrapper only:** `bd solution` stores no state, so git remains authoritative for which branch is checked out where.
- **Traces to:** layered breakdowns lose credibility across handovers (18-1).
