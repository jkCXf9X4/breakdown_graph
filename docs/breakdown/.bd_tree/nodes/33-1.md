# Loader owns filenames, discovery, and views

`loader.py` turns `nodes/*.md` filenames into refs and resolves both the store root and one component.

- **Filename grammar:** `FILENAME` accepts `<id>-<version>.md` and `REF` accepts `<id>-<version>`, with positive integers, no leading zeros, and version at least 1.
- **Store resolution:** `resolve_store_root` accepts a project root or a store root and prefers classic `nodes/` over `.bd_tree/nodes/`.
- **ROOT:** `_read_declared_root` reads one full ref from `<store>/ROOT`; `Store.root_ref` returns it before the lowest available node by `(id, version)`.
- **Membership:** `load_view` walks `Store.neighbors` (authored tokens in both directions) and includes each node once; dangling targets and version collisions are reported by the graph audit while cycles are legal.
- **Inline tokens:** `scan_inline_links` reads `(TITLE)[[REF, TYPE]]` from each body, where the title is an optional prefix and a bare token is valid but warns `inline-title-missing`; it ignores fenced code, inline code spans, and `\[[`, and a malformed fragment is `inline-malformed` (`src/bd_tree/inline.py`).
- **Discovery boundary:** `cli._find_root` walks ancestors and calls `loader.resolve_store_root`, while `load` also accepts either root directly.
- **Implements:** a filename encodes identity and version (23-1).
