# One project has one writable work area

`<project>/bd_work/` is the single writable layout; `bd work REF` replaces its contents, so a second writable folder never exists.

- **Location:** the area is fixed at `<project>/bd_work/`, including a classic `<dir>/nodes/` store where the project root is `<dir>`.
- **Replacement:** a different REF removes stale links, rewrites `INDEX.md`, `REFS.md`, and `AGENTS.md`, and prunes now-empty directories.
- **Query:** `bd current` prints `<project>/bd_work (view <ref>)`; `--path` and `--view` narrow it, and it errors when no area exists.
- **Repair:** `bd work --status` classifies `ok`, `missing`, `wrong-target`, `detached`, `stray`, and `stale-ref`; `--writeback` re-links detached files.
- **Ambiguity:** two areas would leave the current view unclear and two generated headers claiming authority over the folder.
- **Separation:** `bd view` and `bd export` snapshots are read-only and never a second work area.
