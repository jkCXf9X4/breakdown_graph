# Generic markdown importer

An existing markdown tree must be converted by hand into node files with ids, typed body tokens, and front matter.

- **Current behavior:** There is no importer; each document becomes a node through manual file creation and `bd link` edits.
- **Cost:** Migration is slow and error-prone, and reachability or duplicate ids surface only after the tree is built.
- **Possible direction:** Map folders or headings to typed tokens, assign stable ids, and emit a dry-run report before writing nodes.
- **Constraint:** Import must preserve body bytes and avoid inventing schema beyond the structural keys.
- **Changes:** node files are the only source of truth (28-1).
