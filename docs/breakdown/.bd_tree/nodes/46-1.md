# Snapshot list and prune

## Purpose

The operator deciding which read-only projections to keep uses this work item
to bound snapshot housekeeping; without it, disposable pack output accumulates
with no way to list or remove it.

---

Question: do `bd pack` and `bd graph --format` snapshots need a registry that
lists and prunes them, or should each output directory stay an unmanaged,
disposable copy? The cheat sheet defines them as read-only projections and says
only `bd work` is writable, but the command surface has no list or prune verb
(`docs/CHEATSHEET.md:308-331`, `README.md:361-375`).

- Done when: a list command reports existing snapshots with their anchor, path,
  and age, and a prune command removes selected snapshots without touching the
  store or the work area; both leave `bd check` clean, and neither adds a state
  sidecar (`AGENTS.md:112-116`).
- Changes: (One store yields many read-only projections)[[17-1, changes]] would
  be revised by adding snapshot lifecycle.
- Status: suggested; snapshots remain disposable directories with no registry
  (`docs/CHEATSHEET.md:330-331`, `AGENTS.md:112-117`).
