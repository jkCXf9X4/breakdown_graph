# Decisions live in the store as history

## Purpose

The engineer or agent asking why the decision log lives where it does uses this
record to recover the choice and its cost; without it, a separate history store
is proposed again without the rejected alternative.

---

Decision: decision records stay in the same bd store as ordinary
`<id>-<version>.md` files. The entry map reaches the decisions index with a
`records` edge, and the index reaches each record with `breaks_down`; records are
not a state layer. The record is history; the leaves hold current truth.

Rejected alternatives:

1. A separate decisions folder or archive: it would create a second source of
   truth and a second version and merge unit outside the store.
2. Folding records into the state layers: history would be read as current
   state, and live leaves would cite records, which the method forbids.
3. Keeping records outside git: they would lose the per-file diff and merge that
   the flat store gives every node.

Consequence: a record is versioned and linkable by the same tokens as any node,
and git remains its merge unit. History is entered through a `records` edge to
the index, not a state layer, so the six state layers do not depend on history
while the graph stays one component. A record in the same component is in the
default view; "history, not state" is the distinction, not a hidden component. A
live leaf still must not cite a record
(`../../src/agent_methods/methods/product-breakdown/guidelines/history-rules.md:23-29`).

The choice depends on three existing rules.
(A filename encodes identity and version)[[18-1, depends_on]] needs no new file
kind for a record.
(Typed links define the component view)[[19-1, depends_on]] lets one token carry
the history/state distinction.
(Node files are the only source of truth)[[20-1, depends_on]] makes a second
archive a forbidden second source.
