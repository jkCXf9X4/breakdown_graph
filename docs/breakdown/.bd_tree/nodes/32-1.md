# The example store is the clean reference

## Purpose

The test author adding a regression case uses this claim to treat the committed
example as the baseline; without it, a fixture drifts from the store and the
green result stops proving the reference.

---

The committed twelve-node `examples/` store is the reference because the suite
loads it directly and asserts its shape. The test opens both `examples/` and
`examples/.bd_tree/`, requires its declared root ref to resolve, twelve nodes, no placement keys, no
`contains`, and an empty audit (`tests/test_examples.py:39-56`). It then asserts
one component reaching every ref (`tests/test_examples.py:59-65`), a two-parent
node with two derived in-edges (`tests/test_examples.py:68-73`), and the
verification fan-out at distance three (`tests/test_examples.py:76-94`). The ring
table is documented in `docs/GRAPH.md:241-257` and `README.md:405-409`. This claim
verifies (Typed links define the component view)[[19-1, verifies]]: the two-parent
node appears once at its shortest distance. It is falsified if `bd check` on
`examples/` warns, a node is missing, or the committed rings no longer match the
assertions.
