# Three-way merge between versions

Choosing a version means repointing a parent's `contains`, and no base is recorded to merge a second version against it.

- **Current behavior:** `bd contain` and `bd uncontain` (or `bd clone REF` then `bd replace REF NEW`) select which version a parent names; versions carry no `based_on` lineage and the tool has no merge engine.
- **Cost:** Two versions of one node can only be combined by hand, and the losing content is easy to drop.
- **Possible direction:** Offer a diff-and-synthesize path that treats a chosen version as the base and writes a new version, while git stays the history owner.
- **Constraint:** The rejected design kept `based_on` lineage out, so any base must be inferred or supplied explicitly.
- **Changes:** a filename encodes identity and version (23-1).
