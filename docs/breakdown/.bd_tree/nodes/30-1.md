# The work area is a symlink layout

Each node entry in `bd_work/` is a relative symlink to its store file, while `INDEX.md`, `REFS.md`, and `AGENTS.md` are regular generated files.

- **Links:** `_link` writes `os.path.relpath(source, dest.parent)`, so editing an entry edits the store with no copy and no sync (`src/bd_tree/work.py:242`).
- **Generated:** `GENERATED = ("INDEX.md", "AGENTS.md", "REFS.md")` are written as regular files with a do-not-edit banner.
- **AGENTS.md:** names the materialized expression (`REF` or `REF+N`) and the single-area rule, and inside git adds branch, short commit, and worktree path.
- **Depth prefix:** `bd work REF+N` links only nodes within N undirected link hops of the anchor; `_depth_view` filters the rings and the three generated files carry `REF+N`, so `bd current` and `--status` recover the prefix.
- **Status classes:** `ok`, `missing`, `wrong-target`, `detached`, `stray`, `stale-ref` describe every expected path.
- **Writeback:** a detached regular file is copied back only when its front matter parses and a declared `id` matches the ref.
- **Switch guard:** a refresh refuses when detached or stray files would be lost, and `--clean` discards them instead.
- **Traces to:** one project has one writable work area (21-1).
