# Recovery for symlink-replacing editors

An editor that saves by replacing a symlink leaves a detached regular file where the work area expects a link.

- **Current behavior:** `bd work --status` classifies the damage and `bd work --writeback` re-links detached files.
- **Cost:** Every such save breaks the no-copy rule until the user runs a separate inspection and writeback cycle.
- **Possible direction:** Make writeback part of the editor's save path or a watch mode, with the same front-matter and id checks.
- **Constraint:** A body-only replacement must not erase `contains`, so recovery cannot simply keep the detached file.
