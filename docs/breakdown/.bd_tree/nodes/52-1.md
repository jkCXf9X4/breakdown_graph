# Concurrent editor locking

Two writers can edit the same store at once, and nothing coordinates them before git reports a conflict.

- **Current behavior:** The tool takes no lock; git is the conflict detector, and the one work area is not leased to a session.
- **Cost:** Concurrent agent sessions can overwrite each other's edits, and the loss appears only at commit or merge time.
- **Possible direction:** Add an advisory lease over the work area or store for the duration of an edit or command.
- **Constraint:** Stale locks must expire, and a second worktree may legitimately hold another branch.
- **Changes:** ops module performs body-preserving structural edits (35-1).
