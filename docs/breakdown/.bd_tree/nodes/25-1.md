# Structural links define the view closure

`links` is the one edge relation: a view is the forward closure over the structural out-links of one ref, and `band`/`order` place nodes inside it.

- **Closure:** `load_view` walks `Store.children` (authored non-symmetric links) from the ref and includes each node once, so multiple parents are legal (`src/bd_tree/loader.py:603`).
- **Order:** link list order is not display order; layout sorts each band by `order`, then id and version, and `bd link` keeps targets sorted by ref for stable data.
- **No inheritance:** `links` are authored per file; `bd clone` copies the source bytes, `bd clone --subtree` follows structural links then rewires each cloned parent's links to the cloned children, and `bd replace OLD NEW` repoints every inbound link (or `ROOT`) while the old file stays a peer.
- **Cycles:** a repeated ref closes the walk instead of failing; `bd check` reports it as `graph-cycle`, and two reachable versions of one id warn `graph-duplicate-version`.
- **Symmetric links:** one node authors a symmetric master; the opposite is derived at load, marked `[derived]`, never written, and does not expand the closure.
- **Reachability:** every node not reached through a structural link is a topology root; `bd views` lists them and non-anchor roots warn `graph-orphan`.
- **Traces to:** one store yields many read-only projections (22-1).
