# Structural links define the component view

Typed body tokens are the one edge relation: a view is the whole undirected component around one ref, and distance rings order nodes inside it.

- **Membership:** `load_view` walks `Store.neighbors` (authored tokens in both directions) from the ref and includes each node once, so multiple parents and cycles are legal (`src/bd_tree/loader.py:603`).
- **Order:** token order is not display order; the work layout sorts each ring by distance, kind, link type, id, and version, and authored tokens are expected in ascending target order (`graph-unsorted-links` warns otherwise).
- **No inheritance:** tokens are authored per file; `bd clone` copies the source file including its tokens, `bd clone --subtree` follows undirected neighbours (the whole component, or rings 0..N with `--depth`) then rewrites cloned token refs, and `bd replace OLD NEW` repoints every inbound token (or `ROOT`), sets the new live title, and leaves the old file as a peer.
- **Cycles:** a repeated ref closes the walk instead of failing; cycles are legal, and two reachable versions of one id still warn `graph-duplicate-version`.
- **Back-references:** each node authors its own token, so an acknowledged edge is a second authored token with its own type; there is no derived opposite. A cached `(TITLE)` is tool-generated from the target's live title and refreshed by `bd retitle`, and `bd in` marks the reversed in-links `[derived]`.
- **Reachability:** every disconnected component has one representative root; `bd views` lists them and nodes outside the anchor's component warn `graph-orphan`.
- **Traces to:** one store yields many read-only projections (22-1).
