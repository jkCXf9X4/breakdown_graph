# Discovery walks up, then scans down

## Purpose

The operator running `bd` in an unfamiliar directory uses this claim to predict which store a command will read; without it, an edit lands in a sibling project because the resolved store was never confirmed.

---

`bd` resolves the store before it reads a ref: `--root`, then `BD_ROOT`, then the upward walk from the current directory; at each directory a store wins over a `.bd_root` pointer (`src/bd_tree/cli.py:46-80`, `docs/CHEATSHEET.md:19-35`). Only when the upward walk finds nothing does it scan below the current directory to depth 3 and accept exactly one store; several stores are refused with their paths listed (`src/bd_tree/cli.py:61-67`). Discovery finds the store; (Root precedence selects the default view)[[21-1, relates_to]] decides which component is read once the store is found. The failure is silence: two stores below the working directory must be a refusal, not an arbitrary pick, or a command edits a tree the operator never named.
