# A filename encodes identity and version

The ref is the filename: every node file is `<id>-<version>.md`, so identity and version live in one name inside the current checkout.

- **Grammar:** `^(?P<id>[1-9]\d*)-(?P<version>[1-9]\d*)\.md$` — positive integers, no leading zeros, version at least 1 (`src/bd_tree/loader.py:38`).
- **Versions are peers:** `5-1` and `5-2` are two versions of node `5`, and neither is privileged as main.
- **Exact lookup:** a full ref resolves to one file, and a missing ref never falls back to another version or to another branch.
- **One version required:** an id has at least one version file; a bare `<id>.md` is an `invalid-filename`.
- **Front-matter `id`:** optional, and a value that differs from the filename raises `id-filename-mismatch`.
- **Scope:** a version is a tracked file in one branch and is absent from another branch until the branches merge.
- **Traces to:** git owns the solution boundary (20-1).
