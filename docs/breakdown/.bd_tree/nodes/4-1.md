# Architecture — how bd_tree is organized

## Purpose

The architect or reviewer deciding whether a proposed change fits bd_tree's
organizing model uses this node as the invariant set; without it, a change is
argued at the level of a file or command and breaks an invariant silently.

---

The store is organized around one asymmetry: node files carry every authored
fact, and everything else is recomputed from them. The six decisions below are
the architecture invariants; each item states the rule it fixes. All six concern
authored data versus derived output, not a file inventory.

Members, in id order:

1. (A filename encodes identity and version)[[18-1, breaks_down]] fixes identity first, so every later rule can address a ref.
2. (Typed links define the component view)[[19-1, breaks_down]] derives membership from authored tokens once refs exist.
3. (Node files are the only source of truth)[[20-1, breaks_down]] gives every authored fact exactly one home.
4. (Root precedence selects the default view)[[21-1, breaks_down]] picks the component a bare command reads.
5. (The work area is a flat symlink layout)[[22-1, breaks_down]] fixes the single writable layout.
6. (Freshness is opt-in per edge)[[23-1, breaks_down]] tracks staleness only where an edge opts in.

Shared condition: all six hold only while the node files are the single authored
input; a change that adds a placement file, a cached index, or a second writable
folder breaks the set rather than one member. The set is permissive at the edges:
multiple parents, back-edges, and cycles are legal and only a self-loop is
refused (`AGENTS.md:64-66`, `91-92`), freshness is optional per edge so an
untracked edge is not a defect (`docs/DESIGN.md:265-272`), and one store may hold
several components of which `ROOT` names one (`AGENTS.md:118-123`). Only part of
the set is mechanically gated: `bd check` covers filenames, tokens, membership,
and `ROOT`, `bd stale` covers propagating pins, and `bd current --status`
inspects the symlink layout (`docs/GRAPH.md:135-140`, `docs/DESIGN.md:334-335`).
Failure: when a derived artifact is edited as data or a direction label is read
as a membership filter, a fact gains a second home or a member drops out of the
slice.
