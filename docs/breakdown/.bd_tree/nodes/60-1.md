# Decisions stay in the store, linked out of the default view

- **Context:** Decision records are history that explains current state, but a separate archive makes them harder to reach than necessary.
- **Decision:** Keep decisions in the store as their own containment view. Root `1-1` authors the token `[[decision, 10-1]]`; node `10-1` declares `type: decision`; root `1-1` does not contain it.
- **Rationale:** `contains` still decides view membership, so the default work area stays current-state only. The typed token keeps the records reachable and `bd check` clean.
- **Alternative:** A `soft-contains` key was rejected: it adds schema. A typed token keeps the edge compact without one.
- **Consequences:** `bd views` lists the Decisions view; `bd show 1-1 --links` points to it; editing needs `bd work 10-1`.

Superseded in part (topology refactor, 2026-11-20): structural links now decide view membership, so `10-1` sits inside the default view; the records stay in the store but are no longer out of it.

Superseded again (undirected views, 2026-11-25): membership is the undirected component, so `10-1` is in the default component and `bd work 10-1` projects that same component with `10-1` as the active node.

Superseded once more (body tokens, 2026-11-25): link declarations moved out of front matter into the body. Root `1-1` carries `[[decision, 10-1]](Decisions)` inline; the cached title is advisory, per-link freshness lives in the `freshness:` map, and a back-reference is authored, never derived.
