# Ops performs body-preserving structural edits

## Purpose

The maintainer adding a structural command uses this node to route every write
through one byte-preserving, serialized path; without it, a new command
re-renders files and drops unknown front matter.

---

`ops` owns every structural write. `link`, `unlink`, `new_node`, `replace`,
`clone`, `delete`, and `migrate` parse the document, change only token lines and
the `freshness:` map, and reconstruct the file from
`opening + raw_fm + closing + body` (`src/bd_tree/ops.py:191-298` clone,
`300-352` replace, `430-456` delete, `491-663` new/link/unlink, `802-830`
migrate; `src/bd_tree/frontmatter.py:239-272`). `_serialized` wraps each writer in the
store lock, so two commands cannot publish the same sibling or id
(`src/bd_tree/ops.py:147-157`). Bare CLI selectors resolve through the selected
view first, and every write stores the full ref. This module implements
(Typed links define the component view)[[19-1, implements]] by maintaining
authored tokens rather than a derived list. Failure is a writer that calls
`render_document` on an existing node: it re-serialises YAML, drops unknown
keys, and breaks byte preservation.
