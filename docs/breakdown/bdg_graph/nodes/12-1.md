# Large trees need a bounded agent context

## Purpose

The engineer or agent deciding how much of a store a session may read uses this
node as the context bound; without it, read-only projections look optional and a
session opens the whole tree.

---

A large breakdown exceeds what one agent session can hold, so the bounded slice
is the unit of reading. An agent that opens everything sees only the fragments
that fit, cannot tell which of two versions of a fact is current, and edits
against a partial picture (`docs/DESIGN.md:16-17`). bdg fixes one view per
session: a session reads exactly one view and edits through one area
(`README.md:26-27`), and `bdg pack REF --out DIR` writes that view flat while
`--fresh` omits stale bodies (`docs/GRAPH.md:175-187`). The claim is falsified if
an agent holds a large multi-layer tree whole and picks the current node without
a derived view.
