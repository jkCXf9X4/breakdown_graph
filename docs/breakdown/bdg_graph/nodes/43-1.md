# Windows symlink support

## Purpose

The engineer deciding whether the flat work area can run on Windows uses this
work item to bound the symlink gap; without it, the POSIX-only layout is assumed
portable and the Windows path is never tested.

---

Question: can `<project>/bdg_work/` keep its flat symlink contract on Windows, or
must the tool provide a non-symlink layout without adding a second writable
area? The design makes symlinks POSIX-only and requires developer mode on
Windows, and the developer guide records no Windows-specific path
(`docs/DESIGN.md:638`, `docs/DEVELOPING.md:411`).

- Done when: on a Windows checkout without developer mode, `bdg work REF`,
  `bdg edit REF`, and `bdg current --status` behave as on POSIX, and `bdg check`
  stays clean; a copied-file fallback is rejected because it would create a
  second writable layout.
- Changes: (The work area is a flat symlink layout)[[22-1, changes]] would be
  revised by a portable layout; the candidate must settle that rule first.
- Status: suggested; no Windows-specific symlink path exists
  (`docs/DEVELOPING.md:411`).
