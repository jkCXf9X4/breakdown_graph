# Front matter stays project-defined

## Purpose

The integrator deciding whether a metadata field is contractual uses this node as
the schema boundary; without it, project vocabulary is mistaken for a tool
requirement.

---

Front matter belongs to the project, and the tool reserves only the identity and
freshness keys. Everything else — layer names, status vocabularies, group or
section labels — is user data, and the tool adds no schema of its own
(`docs/DESIGN.md:38-39`). Metadata is the cheapest place to copy state across
layers: a field mirrored into every node drifts as soon as the owning layer
changes. The promise realizes
(Layered breakdowns lose credibility across handovers)[[13-1, realizes]] by
leaving the vocabulary where the project can version it with the nodes. It is
falsified by a check that requires a project field, or a command that
writes a placement key instead of leaving `group` inert (`AGENTS.md:78-90`).
