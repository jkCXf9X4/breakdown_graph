# The work area and the git boundary are separate modules

## Purpose

The agent entering a checkout uses this node to distinguish the one writable
area from git branches; without it, edits land in a copy that never reaches the
store or another branch.

---

The work area and the git boundary are separate modules: `work` owns the single
`<project>/bdg_work/` area and its symlink repair, while
`solutions` owns the `git worktree` lifecycle and never writes the area. `work.area` reads the view
from the generated `REFS.md` header, and `work()` builds or replaces the area
with relative symlinks under ring folders by default
(`{distance}/{ref}_{title}.md`, so ring 0 is
`0/1-1_Product Breakdown — bdg.md`), plus generated `INDEX.md`, `AGENTS.md`, and
`REFS.md` and
one `INDEX.md` per folder that directly holds node files; the layout is recorded
in `REFS.md`, `--path-template` overrides it, and `--flat` restores one symlink
per node at its store basename (`src/bdg/work.py:315-338`, `536-622`, `706-760`).
`_link` writes the relative target, and `_inspect` classifies a regular file as
`detached`, blocking a switch until `_writeback` validates it inside `nodes/`
(`src/bdg/work.py:242-250`, `378-406`, `626-640`). `solutions.new` runs
`git worktree add -b`, and `remove` refuses the primary worktree
(`src/bdg/solutions.py:120-160`, `211-238`). The split implements
(The work area is a ring-folder symlink layout)[[22-1,implements]]: a layout change
stays a view switch, and a branch change stays a solution, so neither creates a
second writable copy.
