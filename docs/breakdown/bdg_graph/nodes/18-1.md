# A filename encodes identity and version

## Purpose

The loader author resolving a ref or the reviewer checking where identity comes
from uses this claim to decide whether a name is data or a selector; without it,
a version goes unaddressed and an edit targets the wrong peer.

---

Identity and version live in the filename, not in front matter or a folder.
Every node file is `<id>-<version>.md` with version at least 1, there is no bare
`<id>.md`, and versions of one id are peers with no privileged version
(`docs/DESIGN.md:65-72`, `AGENTS.md:51-52`). A ref in data is always the full
`id-version`, the filename is the authority, and a bare id on the command line is
only a selector inside the view (`docs/DESIGN.md:69-72`). Naming an exact peer
lets a bounded slice be read without deciding which version is current, so the
claim realizes (Large trees need a bounded agent context)[[12-1,realizes]].
Several versions may coexist; a view warns `graph-duplicate-version` when two are
reachable (`docs/DESIGN.md:240-241`). It is falsified by a store that must read
front matter to recover identity.
