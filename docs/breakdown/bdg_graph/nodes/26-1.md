# Loader owns filenames, discovery, and views

## Purpose

The maintainer adding a store layout or discovery rule uses this node to keep
filename grammar and view membership in one place; without it, a second parser
forks identity and a node vanishes from the view.

---

`loader` is the only place that turns filenames into identity and tokens into a
component. `parse_filename` enforces `<id>-<version>.md` and rejects anything
else (`src/bdg/loader.py:95-105`); `scan` reads `nodes/` once and records
`invalid-filename` and `duplicate-version` instead of guessing
(`src/bdg/loader.py:437-480`); `load_view` walks `Store.neighbors` both ways
and returns one `View` with a BFS `distance` map
(`src/bdg/loader.py:551-639`). Discovery is here too: `resolve_store_root`
prefers classic `nodes/` over `bdg_graph/nodes`, and `_read_declared_root`
accepts one full ref from `ROOT` (`src/bdg/loader.py:111-133`, `482-519`).
Thus this module implements (A filename encodes identity and version)[[18-1, implements]].
Failure is a second filename parser or a forward-only walk: refs fork and a
multi-parent node disappears from its view.
