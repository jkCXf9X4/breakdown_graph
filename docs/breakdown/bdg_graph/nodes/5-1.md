# Implementation — where bdg is built

## Purpose

The maintainer routing a code change uses this group to place it in the module
that owns its data-flow stage; without it, a fix lands beside the store scan and
forks filename grammar or byte preservation.

---

Seven module claims, one per module in the map; each item states the invariant
that module protects. `loader.load` produces a `Store` of
every file and edge; `loader.load_view` narrows it to one undirected `View`;
read-only commands consume that `View` or its anchored `Graph`, while structural
commands consume the `Store` and write node files
(`docs/DEVELOPING.md:21-75`).

Members, in id order:

1. (CLI and API share one command surface)[[24-1,breaks_down]] exposes every command once to both callers.
2. (Exporter renders read-only projections)[[25-1,breaks_down]] turns a view into packaged files or a graph render.
3. (Loader owns filenames, discovery, and views)[[26-1,breaks_down]] builds the store and narrows it to one view.
4. (Model and checker separate shape from validation)[[27-1,breaks_down]] turns malformed data into issues rather than exceptions.
5. (Inline scanner preserves body bytes)[[28-1,breaks_down]] reads and maintains tokens without re-rendering prose.
6. (Ops performs body-preserving structural edits)[[29-1,breaks_down]] writes node files for link, unlink, and related moves.
7. (The work area and the git boundary are separate modules)[[30-1,breaks_down]] separates the writable area from the git boundary, so neither copies the other.

Two exception paths bound the flow. `BreakdownError` is a structural refusal and
the CLI exits 2; `NavigationError` is an unresolved read and exits 1;
`ExportError` subclasses `BreakdownError` for unsafe output
(`src/bdg/errors.py:6-10`, `src/bdg/navigate.py:37`,
`src/bdg/cli.py:1086-1096`). The loader does
not raise for bad data: it records an `Issue`, and the checker decides severity
(`src/bdg/checker.py:169-261`).

The shared condition is byte preservation: every writer reconstructs from
parsed front matter plus the untouched body, and only migration may read retired
keys. The failure condition is a second reader or writer outside this split. A
filename regex beside the loader, a body re-render beside the scanner, or a
second work area beside the work module forks identity, freshness, or layout
while `bdg check` still reports clean.
