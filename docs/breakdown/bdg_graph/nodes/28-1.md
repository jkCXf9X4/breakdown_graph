# Inline scanner preserves body bytes

## Purpose

The developer changing token handling uses this node to keep scanning pure and
edits byte-bounded; without it, a rewrite reformats a body and invalidates
freshness pins.

---

`inline` scans a body without rewriting it. `_scan_body` makes one pass tracking
fenced blocks, inline backtick spans, and `\[[` escapes, and records a match
offset for every token plus an anomaly for every malformed `[[...]]` fragment
(`src/bdg/inline.py:167-249`). The editing helpers reuse those spans:
`append_token`, `remove_token`, `repoint_token`, and `retitle_tokens` splice
only the matched ranges and leave every other byte in place
(`src/bdg/inline.py:293-419`). Together they implement
(Typed links define the component view)[[19-1, implements]] at the text layer.
The invariant is purity plus bounded edits, so a token operation cannot reflow
prose or change a freshness hash. Failure is a whole-body regex or a YAML
re-render: whitespace and comments change, and `bdg stale` reports pins that no
author touched.
