# The work area is a ring-folder symlink layout

## Purpose

The author or agent editing through the work area uses this claim to tell a store
path from a copy; without it, an edit is made in a detached file and never
reaches the store.

---

The work area is a layout, not a copy. `<project>/bdg_work/` groups nodes into
ring folders by default: one relative symlink per materialized ref at
`{distance}/{ref}_{title}.md` — ring 0 is `0/1-1_Product Breakdown — bdg.md`,
ring 1 is `1/2-1_Intent — why bdg exists.md`, ring 2 is
`2/4-1_Architecture — how bdg is organized.md` — from the default template
`{distance}/{ref}_{title}.md`, while `INDEX.md`, `AGENTS.md`, and `REFS.md` are
generated regular files reserved in every
directory, and every folder that directly holds node files gets its own
`INDEX.md` (`docs/DESIGN.md:310-318`, `AGENTS.md:99-122`). The title is literal,
spaces included, and `{title}` falls back to the ref when a node has no `title`
front matter. The layout is recorded in
`REFS.md` as `# Layout — {distance}/{ref}_{title}.md`; `--path-template`
overrides it
with any built-in placeholder or front-matter field, and `--flat` restores one
symlink per node at its store basename, recorded as `# Layout — flat`
(`docs/DESIGN.md:342-356`). Editing a link edits the store, with no copy and
no sync layer (`docs/DESIGN.md:310-318`). `bdg work REF`
replaces the area with one view, and `REF+N` materializes rings `0..N` while the
view stays the whole component (`docs/DESIGN.md:323-333`). The active view is the
ref in the `REFS.md` header, so no extra state file exists
(`docs/DESIGN.md:334-336`). One work area holding the whole slice without a
second store is what realizes
(One project has one writable work area)[[16-1,realizes]]. It is falsified
by a copied node file, a sync layer, or an area holding two views.
