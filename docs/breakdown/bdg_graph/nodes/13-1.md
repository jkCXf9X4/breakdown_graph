# Layered breakdowns lose credibility across handovers

## Purpose

The maintainer deciding whether a handover failure is structural uses this node
as the intent claim; without it, copied layer state is treated as a documentation
habit, not the reason the tool exists.

---

A layered breakdown loses credibility at every handover, and the loss is silent:
nothing repairs or detects it downstream by default. A change at one layer
leaves deeper nodes asserting the old solution, so a reader cannot tell which
statement is current (`docs/DESIGN.md:9-18`). Deleting the old branch is the only
well-defined removal and loses the reasoning behind the change
(`docs/DESIGN.md:19-20`). It is the time dimension of
(Credibility belongs to the producing chain)[[11-1,relates_to]]: the chain holds
until a copy severs it. The tool makes dependencies authored tokens and stale
material visible (`docs/DESIGN.md:22-24`); the claim is falsified if
hand-maintained layers repair a top-layer change without copied state.
