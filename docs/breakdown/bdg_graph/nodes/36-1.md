# Install and upgrade preserve the store

## Purpose

The operator installing or upgrading the package uses this claim to keep the store out of the code deploy; without it, an upgrade is assumed to rewrite node files and the team either avoids it or converts by hand.

---

Installing or upgrading bdg replaces the package code that the `bdg` entry point runs; it never rewrites a store's node files. The install path is a plain `pip install .` from the clone (`README.md:83-96`), and the package declares no install hook or data migration (`pyproject.toml:1-30`). Install and upgrade operate the command surface in (CLI and API share one command surface)[[24-1, operates]], not the store. Conversion is a separate, explicit, idempotent operation, not part of install: (Migration converts retired data)[[37-1, relates_to]] owns the conversion path and its dry run. The failure is an upgrade that auto-converts: it would change history under the operator, make a rollback depend on git, and remove the chance to inspect a dry run.
