# Exit codes separate success, navigation, and structure

## Purpose

The script author or agent driving the command line uses this claim to branch on
the process result; without it, a structural refusal is handled as a plain check
failure.

---

The CLI separates three outcomes. Zero means success with warnings allowed: a
check that reports an oversize warning still returns 0
(`tests/test_cli.py:331-334`). One means a reported failure or an unresolved
navigation: `check` returns 1 on an error (`tests/test_cli.py:10-14`) and `show`
returns 1 for a selector outside the view (`tests/test_cli.py:408-416`). Two
means a structural refusal or usage error: a malformed depth suffix
(`tests/test_cli.py:461-469`), an `edit` outside the materialized prefix
(`tests/test_cli.py:484-485`), and a refused `delete` or `replace`
(`tests/test_cli.py:109-120`, `tests/test_cli.py:187-192`) all return 2. This
claim verifies (CLI and API share one command surface)[[24-1,verifies]]: the
tests call `main` and read its integer result while the API raises
`BreakdownError` for the same refusal. It is falsified if a structural refusal
returns 0 or 1, or a check error returns 0.
