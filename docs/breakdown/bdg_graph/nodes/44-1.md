# Generic markdown importer

## Purpose

The engineer deciding whether existing markdown can enter the store uses this
work item to bound an importer; without it, migration is assumed to ingest
arbitrary prose and import scope stays undefined.

---

Question: can bdg import a generic markdown tree — headings, relative links, and
prose — as versioned nodes, or does conversion stay limited to the classic
bare-file and containment stores that `bdg migrate` already handles? The
developer guide names the generic importer as not built and limits migration to
in-place conversion (`docs/DEVELOPING.md:402-405`).

- Done when: an import command maps a directory of markdown files to
  `<id>-<version>.md` nodes with full refs and typed tokens, reports a dry-run
  plan, and the result passes `bdg check` without hand editing.
- Changes: (A filename encodes identity and version)[[18-1, changes]] would be
  extended by an importer that allocates ids and versions, so the rule must
  accept what the importer emits.
- Status: suggested; no importer exists, and `bdg migrate` remains the only
  conversion path (`docs/DESIGN.md:549-577`).
