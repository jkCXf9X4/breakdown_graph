# CLI and API share one command surface

## Purpose

The integrator scripting bdg uses this node to rely on one command surface for
both shell and Python callers; without it, a command exists only behind argv and
automation must shell out.

---

The structural and load/check commands exist once as public functions in
`api.py`, with `cli.py` adding only argparse wiring and output formatting; the
read-only renderers (`show`, `find`, `path`) are CLI-only because they format for
humans. `api` re-exports the loader, graph, ops, work, and solution operations
unchanged (`src/bdg/api.py:70-139`), and `cli.main` parses arguments, calls
`args.func`, and maps exceptions to exit codes (`src/bdg/cli.py:1086-1096`).
Root resolution is the shared seam: `cli._find_root` applies `--root`, `BDG_ROOT`,
the upward store walk, then a unique downward scan (`src/bdg/cli.py:46-79`),
which is how this module implements
(Root precedence selects the default view)[[21-1,implements]]. The invariant is
one surface for structural work: a Python caller and a shell caller reach the same
function. Failure is a structural command implemented only in the CLI, forcing
subprocess use and a second root resolution; a renderer implemented twice is the
cheaper exception.
