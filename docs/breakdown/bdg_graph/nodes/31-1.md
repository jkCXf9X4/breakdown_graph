# Check validates store and view invariants

## Purpose

The agent or reviewer deciding whether a store is safe to use uses this node as
the acceptance gate; without it, a structural defect ships because only the happy
path was read.

---

`bdg check` must validate the store and the selected view in one pass: filenames
and refs, retired `contains`/front-matter `links`, token grammar, dangling
targets, duplicate versions, size, and component membership. It verifies
(Typed links define the component view)[[19-1, verifies]] and warns on
(Freshness is opt-in per edge)[[23-1, verifies]]; it exits 1 on any error. It
must not claim to validate prose, purpose presence, or a detached `## Links`
section, because it never compares prose with the graph.

- Now: the check covers the store scan and the selected closure; `bdg stale` is
  the view-scoped freshness list (`docs/GRAPH.md:135-173`).
- Blocked by: no blocker for the structural gate; a green check can still hide
  a prose defect, which is a review finding, not a check failure.
- Done when: `bdg check` exits 0 and every `bdg stale` row is explained or fixed
  (`docs/GRAPH.md:135-173`).
