# Detached edits block a switch until repair

## Purpose

The operator switching the work area uses this claim to keep an editor's detached copy from being discarded; without it, `bdg work REF` refuses the switch and the edits are neither written back nor deliberately dropped.

---

Some editors replace a symlink with a regular file; the area reports that path as `detached` and a refresh refuses rather than overwrite it (`src/bdg/work.py:49-52`, `src/bdg/work.py:507-522`). The repair path operates the (The work area is a flat symlink layout)[[22-1, operates]]: `bdg current --status` names each entry, then `bdg work --repair` copies the edit back into the store and re-links it, while `--clean` discards it (`AGENTS.md:125-152`, `docs/CHEATSHEET.md:164-237`). `--repair` refuses invalid front matter or a mismatched `id`, so a bad file is reported rather than written over a node (`docs/GETTING-STARTED.md:220-221`). The failure is forcing the switch or deleting the file: the store loses an edit that was never committed.

- Now: a switch with a detached or stray file is refused (`src/bdg/work.py:507-522`).
- Blocked by: the operator choosing repair or clean; neither runs automatically (`docs/CHEATSHEET.md:164-237`).
- Done when: `bdg current --status` reports every entry `ok` and the view has switched (`docs/CHEATSHEET.md:164-237`).
