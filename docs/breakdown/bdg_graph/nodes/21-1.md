# Root precedence selects the default view

## Purpose

The operator running a bare command uses this claim to know which component will
be read and how to override it; without it, a command silently resolves a
different component and reports an unrelated node clean.

---

The default view is chosen by fixed precedence, not by the last command run. An
explicit ref wins; otherwise `ROOT` names the anchor; otherwise the lowest member
of the first component is used (`AGENTS.md:118-123`, `docs/DESIGN.md:192-199`).
A declared but missing ref is `root-ref-missing` and is never silently replaced;
malformed content is `invalid-root` (`AGENTS.md:118-123`).
`bdg check --view REF` only narrows reporting, and this default is separate from
the area's view, which changes only with `bdg work REF` (`AGENTS.md:120-123`). A
deterministic default keeps one bounded slice reproducible, so the claim realizes
(Large trees need a bounded agent context)[[12-1, realizes]]. Many components may
coexist and `ROOT` names one; that plurality is the exception. It is falsified
when a command resolves an anchor other than `ROOT` while `ROOT` is present.
