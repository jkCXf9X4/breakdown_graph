# Migration converts retired data

## Purpose

The operator holding an older store uses this claim to run the one conversion path before browsing; without it, retired `contains` or front-matter `links` fail `bdg check` and the store looks corrupt.

---

Migration is the single, explicit conversion: `bdg migrate [--dry-run] [--type T]` versions bare `nodes/<id>.md` files, converts `contains` and front-matter `links` into typed body tokens in a trailing `## Links` section, moves pins into `freshness:`, normalizes tokens, fills titles, and strips retired placement keys (`README.md:165-192`, `docs/CHEATSHEET.md:57-89`). It operates the identity rule in (A filename encodes identity and version)[[18-1,operates]]: the versioned filename is written before links are converted. It is idempotent; `--dry-run` prints the plan without touching disk (`src/bdg/ops.py:802-830`). The failure is stopping at the command: the converted tokens sit in a detached section (`README.md:168-171`), so a structural check passes while the sentences carry no links.

- Now: a store still declaring `contains` or front-matter `links` fails `bdg check` (`README.md:172-175`).
- Blocked by: nothing structural; run `bdg migrate --dry-run` before applying it (`README.md:186-192`).
- Done when: the tokens sit in their asserting sentences and `bdg check` exits 0 (`AGENTS.md:81-90`).
