# Temporary stores drive the test suite

## Purpose

The test author adding a case uses this claim to justify building a real store
under `tmp_path`; without it, a mock replaces the loader and the case stops
exercising discovery, parsing, and checking.

---

The suite's substrate is a real temporary store, not a mock. `write_node` writes
arbitrary front matter and canonical body tokens into a directory under
`tmp_path`, and `make_store` builds the twelve-node default with a final
`retitle` pass so the fixture checks clean (`tests/conftest.py:160-204`,
`tests/conftest.py:291-311`). `docs/DEVELOPING.md:258-260` states the rule: use
`tmp_path` and real files, and do not mock the loader. The claim verifies
(Model and checker separate shape from validation)[[27-1, verifies]]: a case writes a
store, then reads it through the same loader and checker the CLI uses, so shape
and validation are tested together. The stale view test builds its nodes this way
(`tests/test_stale.py:12-44`). It is falsified by a case that mocks the loader or
asserts against an in-memory model with no store on disk.
