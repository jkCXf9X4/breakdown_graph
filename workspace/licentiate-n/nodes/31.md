# Encode the multi-level ownership rule for the article layers

The migrated tree maps the kappa at four abstraction levels: thesis meaning (`intent/ claims/ argument/`), paper evidence (`evidence/`), kappa presentation (`manuscript/`), and build and release artifacts (`operation/`), with `evolution/` as the work level.

**Evidence:** the root README states the levels once, but the rules for agents (`AGENTS.md`) do not; a fact restated two levels up is the same defect the migration removed, and nothing reviews for it — the layer model alone does not stop a new leaf from copying a paper result into a chapter node.

**Change:** `AGENTS.md` gains the level table and the citation rule — a fact is written once at the level that owns it, a higher level cites it by ID and never restates it, and a change starts at the lowest level it affects and moves upward only through citations. The root README gains one line pointing at the rule, and `review/criteria.md` (`30`) names "fact restated at the wrong level" as a routing criterion.

**Risk:** small — one rules-file edit, one review criterion, no structural change; the blast radius is the next agent edit, which is exactly the defect this prevents.

**Acceptance:** `AGENTS.md` carries the four-level table and the write-once/cite-up rule; `review/criteria.md` lists cross-level restatement as a finding type that routes to the owning leaf; `pb check --strict` and `pb node-size --strict` stay green.
